# style-guide: デザイントークン使用規約

ADR-012(`docs/design/12_ADR-012_デザイントークンとスタイルガイド.md`)のS2(文書化)を
担うスキル。**どのトークンを・いつ・どう書くか**の実務手順のみを扱う。なぜこの配色・
体系にしたかという設計判断の背景は本ADRを参照し、ここでは繰り返さない。

## 1. 前提: 現在地(S1完了・S3未着手)

- **S1完了**: `app/globals.css` の `@theme static` ブロックにトークンが定義済み
  (PR#150)。**既存コンポーネントへの適用はまだ行われていない**。
- **S3未着手**: `components/ui/`(`Button`/`Card`/`FormField` 等の共通部品)は
  **まだ存在しない**。ADR-012 §2.3 で計画されているが、これは別タスクのスコープ。
  このスキルの範囲でボタン等の共通コンポーネントを新設しない
  (CLAUDE.md規則1、スコープ外作業の禁止)。
- したがって現時点でできることは、**Tailwindクラスとして直書きする際に
  色の指定にトークンを使う**ことのみ。この使い分けは §5〜7 を参照。

## 2. トークン一覧と用途

`app/globals.css` の `@theme static` に、各カテゴリ `50`(最も明るい)〜`900`
(最も暗い)の10段階スケールで定義されている。値そのものの正は `app/globals.css`
であり、ここでは重複させない(数値を変更する場合はそちらを編集し、ここは
用途の説明のみを保つ)。

| カテゴリ | トークン | 用途 |
|---|---|---|
| ブランド | `--color-brand-50`〜`900` | プライマリボタン、リンク、アクティブ状態、フォーカスリング |
| セマンティック(danger) | `--color-danger-50`〜`900` | エラーメッセージ、削除操作、失敗状態 |
| セマンティック(success) | `--color-success-50`〜`900` | 成功メッセージ、合格状態、完了表示 |
| セマンティック(warning) | `--color-warning-50`〜`900` | 警告、注意喚起 |
| セマンティック(info) | `--color-info-50`〜`900` | 補足情報、Callout(info) |

ニュートラル(灰色系・本文/境界線/背景)はトークン化していない。§6 参照。

## 3. Tailwindでの参照方法

Tailwind v4は `@theme` で定義した `--color-*` 変数を自動的にユーティリティ
クラスへ展開する(追加設定不要)。`bg-`/`text-`/`border-`/`ring-`/`outline-`
などの色系ユーティリティすべてで、通常のTailwindパレット色と同じ書き方で
使える。

```tsx
// プライマリボタン(ブランド)
<button className="bg-brand-500 text-white hover:bg-brand-600 active:bg-brand-700
                    dark:bg-brand-400 dark:text-neutral-950 dark:hover:bg-brand-300">
  送信
</button>

// エラーメッセージ(danger)
<p className="text-danger-700 dark:text-danger-400">
  入力内容にエラーがあります
</p>

// 成功状態のCallout(success)
<div className="rounded border border-success-200 bg-success-50 text-success-800
                 dark:border-success-800 dark:bg-success-900/40 dark:text-success-300">
  演習に合格しました
</div>
```

### シェード選定の目安(既存の`neutral-*`運用に合わせる)

このリポジトリの既存コード(`app/globals.css`の`.lesson-article`関連ルール等)で
`neutral-*` が実際にどう使われているかに揃える。新規トークンも同じ濃淡パターンを
踏襲すること。

| 用途 | ライト | ダーク |
|---|---|---|
| 背景(強調ブロック) | `50`〜`100` | `900`(必要なら`/40`等で不透明度を下げ、`neutral-900/40`の既存パターンに倣う) |
| 境界線 | `200` | `800` |
| 文字色 | `700`〜`900` | `300`〜`400`(暗い背景でも十分なコントラストになる明るめのシェード) |
| 塗り(ボタン等の主要面) | `500`(base) / `600`(hover) / `700`(active) | `400`(base) / `300`(hover) |

これは出発点であり絶対値ではない。実装時は実画面でコントラストを確認し
(`verify-webapp`スキル)、必要なら隣接シェードに調整してよい。

## 4. アクセシビリティ

WCAG AA(本文コントラスト比4.5:1以上)を満たすシェードを選ぶ。特に
`danger`/`warning` は彩度が高く明るいシェード(`400`以下)を白背景の文字色に
使うとコントラスト不足になりやすいため、文字色には`700`以上を優先する。

## 5. 新規の色指定ルール(必須)

**新規にUI要素へ色を指定する場合、Tailwindの生デフォルト値
(`red-600`/`emerald-500`/`amber-400`/`sky-400`等)を直接使わず、対応する
セマンティックトークンを使う。**

| 直書きしない例 | 代わりに使うトークン |
|---|---|
| `red-*`, `rose-*` | `danger-*` |
| `green-*`, `emerald-*` | `success-*` |
| `amber-*`, `yellow-*` | `warning-*` |
| `blue-*`(補足情報用途) | `info-*` |
| `sky-*`(ブランド用途) | `brand-*` |

この規約は**新規に書くコード**にのみ適用する。既存コードへの遡及適用は
S4(セマンティックカラー統一)のスコープであり、このルールを理由に
無関係なファイルを書き換えない(§7参照)。

## 6. ニュートラルカラー

灰色系(本文・境界線・背景)は既存の Tailwind `neutral-*` を**そのまま継続
使用**する(ADR-012 §2.2, §4.3)。トークン化・置き換えの対象ではない。
`neutral-*` は既に一貫して使われており、変更の利益がないと判断されている。

## 7. 移行期間中のルール(ADR-012 §3.1)

- **新規に追加する視覚要素**は、その時点で利用可能な共通部品・トークンを使う。
  `components/ui/` はまだ存在しない(§1)ため、色の指定にトークン
  (`brand-*`/`danger-*`等)を使いつつ、要素自体はTailwindクラス直書きで
  実装してよい。
- **既存箇所を「ついでに」書き換えない**(CLAUDE.md規則1のスコープ限定)。
  自分のタスクに無関係なファイルの `red-600` 等を見つけても、そのタスクの
  範囲外なら手を出さない。
- 置き換えタスク以外で `app/globals.css` の `@theme` や(将来の)
  `components/ui/` を変更する必要が生じた場合は、理由を完了報告に明記する。

## 8. 検証

このスキルの適用はTailwindクラス文字列の選択のみであり、通常は追加の
検証手順を要しない。色指定を含むUI変更を行った場合は、他のUIタスクと
同様に `npm run lint && npm run typecheck && npm run test && npm run build`
を実行し、UI変更であれば `verify-webapp` スキルの手順で実画面を確認する。
